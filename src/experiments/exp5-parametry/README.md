количество запросов при смене фильтра
порядок ответов
соответствие отображаемого результата выбранному фильтру
наличие промежуточного сброса данных или мигания интерфейса

В качестве параметра запроса используется фильтр списка данных. При изменении фильтра приложение должно либо выполнить новый запрос, либо использовать ранее полученные данные, если это допускается логикой реализации.

Метод для 5a
5a. Изменение параметров запроса

Цель подпункта:
Проверить, как приложение реагирует на обычное изменение параметра запроса, и сравнить число HTTP-запросов и согласованность отображаемых данных в ручной реализации и в реализации с TanStack Query.

Метод:
В интерфейсе создаётся компонент со списком элементов и переключателем фильтра. В качестве значений фильтра используются, например, all, active, completed. При первом открытии страницы выполняется запрос на получение данных для начального параметра. После этого пользователь последовательно изменяет фильтр. Для каждого нового значения инициируется получение соответствующего набора данных.

В ручной реализации изменение фильтра приводит к повторному запуску useEffect, зависящего от текущего параметра. В реализации с TanStack Query изменение параметра приводит к изменению queryKey, что инициирует получение данных для нового ключа запроса.

Во время выполнения фиксируются:

количество запросов при смене фильтра
порядок ответов
соответствие отображаемого результата выбранному фильтру
наличие промежуточного сброса данных или мигания интерфейса

Ожидаемый результат:
Обе реализации должны корректно обновлять данные при обычной смене параметра, однако TanStack Query обеспечивает более структурированное и предсказуемое поведение за счёт явной зависимости данных от queryKey.
